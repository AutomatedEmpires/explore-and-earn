# Seeker `/map` — interactive Mapbox map

The real interactive map surface for the seeker `/map` route. Mapbox is the
founder-locked map provider (decision 2026-06-05); this replaced the Sprint-Zero
location-grouped index (`OpportunityMap`, retained as a non-routed fallback).

## Pieces

- **`MapView.tsx`** — the only client component (`"use client"`). Renders
  `react-map-gl` + `mapbox-gl`, centered on the USA at zoom 4. One marker per
  listing that has `coordinates`; clicking a marker opens that listing's
  canonical `DiscoveryCard` (`surface="map"`) in a popup. Handles loading
  (`Skeleton`), empty (no geocoded listings), and error / missing-token states.
- **`app/(seeker)/map/page.tsx`** — stays a **server component**. Fetches via
  `getDiscoveryListings()` and passes listings + `?focus=<id>` to `MapView`.

## Data seam

Marker positions come from the optional `coordinates { lat, lon }` field on the
local `DiscoveryListing` view-model (`components/discovery/listing.ts`). The
frozen `@explore-and-earn/contracts` Listing object model is intentionally NOT
touched — when the persisted contract + geocoding land, `coordinates` is sourced
from the resolved address instead of the fixtures. Listings without coordinates
(e.g. "Remote · Worldwide") are omitted from the map by design.

## Runtime config

`NEXT_PUBLIC_MAPBOX_TOKEN` is provided at runtime via Doppler
(`process.env.NEXT_PUBLIC_MAPBOX_TOKEN`). When it is absent the map renders the
graceful "Map unavailable" state instead of throwing.

## Note on the lockfile

This change adds `react-map-gl` + `mapbox-gl` to `apps/web`. `pnpm-lock.yaml`
must be regenerated by running `pnpm install` (CI installs with
`--frozen-lockfile=false`, which updates the lockfile during the install step).
