# Seeker (Sub-project 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build sub-project 4 of Explore&Earn. A seeker builds a profile that is their resume, applies with an immutable application, and tracks it. The safety module (reports, blocks, mutes) ships here, and every later sub-project reuses it.

**Architecture:** Three new modules go into the Foundation modular monolith: `src/modules/profiles`, `src/modules/applications` and `src/modules/safety`. Imports point one way: applications → profiles → safety.

- **Client-safe code:** types, zod schemas, copy and pure rules live in `src/lib/{profiles,applications,safety}`. Screens and the `src/app/_features` UI import only these and the HTTP API, never server code.
- **Phase A (W0)** lands every contract as a typed stub: module indexes, every route file with its `apiRoute` options, migration shells, touchpoints, notification types and test fakes.
- **Then:** W1–W5 build in parallel worktrees on disjoint files, W6–W7 build the screens and shared UI, and W8 proves the exit criteria.

## Global Constraints

- **Foundation's constraints all apply:**
  - Tooling: pnpm, strict TypeScript, `no-explicit-any` set to error.
  - Tables: in the `app` schema, with RLS on and no policies. IDs from `newId()`. CHECK enums. `created_at` and `updated_at` with `app.set_updated_at()`.
  - Module imports go through `@/modules/<name>` only. No raw colors outside `src/ui`. Errors use the error envelope.
  - Accessibility: contrast, 44 px touch targets, `aria-label` on icon-only controls.
  - Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never push.
- **Migration ranges:**

  | Range | Owner |
  |---|---|
  | 3000 | W0 (the full DDL, Task 7) |
  | 3001–3049 | W1 |
  | 3050–3099 | W3 |
  | 3200–3299 | W4 |
  | 3300–3399 | W5 |

  W0 creates the shells `drizzle/3000_profiles.sql`, `3050_profiles.sql`, `3200_applications.sql` and `3300_safety.sql`, then replaces the 3000 shell with the full profile DDL in Task 7.
  - **Engineering decision** (spec section 12 gives 3000 to W1): W3's `3050` references `app.seeker_profiles`, and W3's import code reads and writes the profile and entry tables. A `select 1;` shell in W3's worktree would make 3050 fail to apply, so the 3000 tables land in Phase A.
- **Foreign keys** point only to `app.users`, `app.organizations`, `app.media` and SP4's own tables. Listing IDs are plain `uuid` columns, validated through SP2.
- **Month columns** are `date` with CHECK `extract(day from x) = 1`.
- **Date formats:**
  - At the API and in snapshots, months are `'YYYY-MM'` and dates are `'YYYY-MM-DD'`.
  - Timestamps in DTOs are ISO strings.
- **Import direction:** `applications → profiles → safety`. Each of the three may call `@/modules/{listings,hostpages,orgs,locations,discovery}`. Route files in `src/app` may compose any of them.
- **Client-safe code:** `src/lib/{profiles,applications,safety}/**` never value-imports `@/modules/*`, `@/lib/db` or `drizzle-orm` (`import type` is allowed).
- **Refusals** use Foundation codes, with `details.reason` naming the SP4 case. For example, `listing_closed` is `409 conflict` with `details: { reason: 'listing_closed' }`.
- **"host\*"** means:
  - `auth: 'host'`;
  - the role is in `owner`, `admin` or `recruiter`, otherwise `403` with `details.reason: 'role_not_allowed'`;
  - and `canAccessListing`, otherwise `404`.

  Billing members get 403 on every SP4 host route.
- **Rate limits** (the window is always `86400` seconds):

  | Key | Limit |
  |---|---|
  | `apply:<userId>` | 30 |
  | `ai_import:<userId>` | 5 |
  | `writing_help:<userId>` | 30 |
  | `reports:<userId>` | 20 |
- **AI:** only through `generate` with model `claude-sonnet-5-5`. Prompts live in `src/modules/profiles/prompts/`. Implementers who touch `src/lib/ai.ts` or a prompt load the `claude-api` skill first.
- **Logs, audit data and analytics** never hold profile text, answers, resume text, contact details or prompts.
  - Audit `data` holds field names and enum codes only.
  - PostHog events are exactly `application_submitted { listingId, source }`, `resume_import_finished { status }`, `writing_help_used { field }` and `report_created { subjectType, reason }`.
- **Delivery and disclosure:**
  - PDFs are sent with `Cache-Control: private, no-store`. Private media is reached through 300-second signed URLs, issued only after SP4 has authorized the viewer.
  - A blocked host sees `not_found`, never "blocked".
  - Certifications are labeled "Self-reported" everywhere.
- **Copy:**
  - Every string the spec quotes is used verbatim: missing-item lines, dialogs, consent, empty states and failure lines.
  - **Explore&Earn** is written exactly like that, and the interface has no emoji.
  - Copy beyond the spec (labels and titles) is plain and warm, and addresses the reader as "you".
- **Screens** use only `src/ui` components and tokens.
  - Loading uses `Skeleton`; errors use `ErrorState` with Retry. Mobile is below 768 px.
  - axe finds 0 serious or critical violations at 390 px and 1280 px.
- **Resume templates** are only ever added, never edited. `classic@1` and `compact@1` are frozen by golden files.
- **No server-side apply drafts:** in-progress answers live in `sessionStorage`.
- **Build environment:**
  - Windows, no Docker.
  - Unit tests run on PGlite (`pnpm test`). `*.int.test.ts` files run only in CI (`pnpm test:integration`).
  - SP4 adds no environment variables.
- **Ownership:**
  - A workstream edits only the files its tasks list.
  - Only W0 edits shared files: `package.json`, the configs, `src/db/schema.ts`, `src/server/*.ts`, the openapi import list, `src/ui/components/index.ts` and the seeker shell.

## Review Focus

These are input classes the spec implies but no spec test exercises. Each has its own test in the task named.

1. **A seeker who withdrew tries to apply to the same listing again.** The unique `(listing_id, seeker_user_id)` means no second application. The apply page must say so and link the receipt, never show a form that silently returns the old application.
   - Server: Task 20 (submit returns the withdrawn application with `created: false`) and Task 22 (the context returns `existingApplicationId`).
   - UI: Task 30.
2. **A seeker west of UTC near midnight.** In Honolulu at 20:00 on Dec 2 it is 06:00 Dec 3 UTC. `clientToday` is one day behind the server, and "Now" must store Dec 2, not be rejected or shifted. Task 10.
3. **An application deadline passes** (SP2's `canAcceptApplications` returns `deadline_passed`) while the listing stays `active`. Submitting must return 409 `listing_closed`, not a 500, and the apply page must show the closed state.
   - Server: Tasks 20 and 22. UI: Task 30.
4. **Names outside ASCII** ("José Núñez") in a resume PDF and its download file name.
   - The text must extract intact (Task 13).
   - `Content-Disposition` must carry an ASCII fallback plus `filename*` (Task 14).
5. **The listing is closed or removed after the seeker applied.** My jobs rows, the receipt and the application PDF must still render from the frozen snapshot, with no SP2 lookup that could 404.
   - Rows and receipt: Task 22. PDF: Task 14.

### Task 2: `generate` with PDF documents

**Files:**

- Modify: `src/lib/ai.ts`
- Create: `src/lib/ai.generate.test.ts`

**Interfaces:**

- **Consumes:** Foundation's `ClassifyContent` and its env-selected provider in `src/lib/ai.ts`.
- **Produces** (from spec 3.4):

  ```ts
  export type AiContent = ClassifyContent | { type: 'document'; mime: 'application/pdf'; bytes: Uint8Array };
  export class AiError extends Error { readonly kind: 'timeout' | 'refusal' | 'schema' | 'provider' }
  export function generate<T>(opts: { model: 'claude-sonnet-5-5'; system: string; content: AiContent[]; schema: z.ZodType<T>;
    promptVersion: string; effort: 'low' | 'medium'; timeoutMs: number; maxTokens: number; stub: (c: AiContent[]) => T }): Promise<T>;
  ```

  If SP2 or SP8 already added a Sonnet call, keep it and add only the `document` content type and anything missing from this signature.

- [ ] **Step 1: Write the failing tests.** Mock `@anthropic-ai/sdk` with `vi.mock`, and switch `AI_PROVIDER` through `process.env` plus `resetEnvCache()`.
  - **Stub provider:**
    - It returns `schema.parse(stub(content))`.
    - Both markers are found in text content and in document bytes (a latin1 scan of the bytes, so a marker in a PDF's `info.Keywords` counts, as Task 16 relies on):
      - `__fail__` rejects with `AiError` `kind: 'provider'`;
      - `__refuse__` rejects with `kind: 'refusal'`.
    - Four tests, one per marker and content type: `__fail__` in text, `__fail__` in document bytes, `__refuse__` in text and `__refuse__` in document bytes.
    - A stub value the schema rejects gives `kind: 'schema'`.
  - **Anthropic provider, the captured request:**
    - `model: 'claude-sonnet-5-5'`, `fallbacks: 'default'`, `betas` containing `'server-side-fallback-2026-07-01'`
    - `output_config.effort: 'medium'` and `output_config.format.type: 'json_schema'`
    - `content[0]` is `{ type: 'document', source: { type: 'base64', media_type: 'application/pdf', data: <base64 of the bytes> } }`
    - there is no `tool_choice`, `thinking`, `temperature` or `top_p`
  - **Anthropic provider, the response:**
    - `stop_reason: 'refusal'` → `kind: 'refusal'`
    - a text block `'not json'` → `kind: 'schema'`
